# Art Pipeline — Blender → Three.js

All 3D art is made in **Blender** (4.x/5.x) and exported as **glTF binary (.glb)**.
Sources live in `art/blender/`, exports in `public/assets/models/`.

```
tools/blender/build/   props.py  enemies.py  viewmodels.py  shore.py  wreck.py  beacon.py
tools/blender/lib/     kit.py (shared helpers: B(), materials, mesh builder, terrain, export)
art/blender/
  props/props.blend              every PROP_<id> (nodes, crates, lanterns, boat…)
  enemies/enemies.blend          every MODEL_<enemy id>
  viewmodels/viewmodels.blend    VM_boltcaster_mk1/mk2, VM_lamplighter, VM_lantern, VM_rod_*, VM_bobber
  locations/shore.blend  wreck.blend  beacon.blend
public/assets/models/
  props.glb  enemies.glb  viewmodels.glb       loaded once at boot, cloned by name
  locations/<id>.glb                            loaded when you travel there
```

Lantern's Rest (home) is built in code (`src/world/home/HomeLevel.ts`) because so
much of it changes with progression.

## Building

The art is generated by Python scripts so it can be rebuilt and diffed:

```bash
npm run build:art
```

```bash
npm run build:art -- wreck beacon
```

Each script writes its `.blend` and exports the `.glb`. Blender runs headless
(`-b`), one script at a time, about a second each, so it never touches a Blender
window you have open. The scripts find Blender via `$BLENDER`, then `blender` on
PATH, then the Steam and blender.org install folders. Order matters: locations
append props from `props.blend`, so `props` builds first (the default order does
this).

To hand-edit instead: open the `.blend`, change it, and export with
`npm run export:models` (exports every `.blend` whose `.glb` is older). Note that
re-running that level's build script overwrites hand edits, so move anything
you want to keep into the script.

Preview a file without opening Blender:

```bash
blender -b art/blender/locations/wreck.blend --python tools/blender/preview.py -- .previews/wreck.png 200 38
```

`tests/levels.test.ts` reads the exported levels and checks the markers below and
the node/enemy counts against `src/data/locations.ts`.

## Scale & orientation

- **1 Blender unit = 1 metre.** Player eye height 1.65 m, radius 0.35 m, jump
  ≈ 1.08 m, dash 6 m. Steps up to ~0.3 m are walked over; keep ramps ≤ ~25°.
- Scripts work in **game space** (+Y up, metres) and convert with `kit.B(x, y, z)`
  (game +Z is Blender −Y). Models face game +Z (Blender −Y, the Front view).
- **Tide heights:** low water y 0.0, high water y 1.8. Wading from 0.5 m deep,
  swimming from 1.1 m; after 6 s swimming the current rescues you to an anchor.

## Object naming — the game reads these

| Name / property | On | Meaning |
|---|---|---|
| `COL_*` | mesh | Collision only, hidden in game |
| prop `col: 1` | mesh | Visible **and** solid (terrain, hull, decks) |
| `SPAWN_<name>` | empty | Arrival point; its Z rotation is the facing. `landing` (boat), `path` (shore cliff path), `ladder` (wreck rope ladder) |
| `ANCHOR_*` | empty | Where the rescue current takes you. Ground level only, never somewhere that skips a route |
| `NODE_*` + prop `node` | empty or prop | Gather node, id from `src/data/nodes.ts`. A prop placed here is the visible node |
| `ENEMY_*` + props `enemy`, `tide` | empty | Spawn; `tide` is `low`/`high`/`any` |
| `INT_*` + prop `interact` (+ `range`) | any | Interactable: `boat`, `path_home`, `rope_ladder`, `beacon`… Any object with an `interact` prop works, so a `BUOY_boat` can be the boat |
| `BUOY_*` + props `float`, `min`, `max` | mesh | Floats: origin at water + `float`, clamped to `min..max`. Its bounding box is something you can stand on |
| `TRIG_*` + prop `event` | mesh | Hidden volume; entering fires `event` (`boss`, or `toast:<text>` for a one-time hint) |
| `STATE_<flag>_<on\|off>` | any | Shown only when the flag is set (`on`) or unset (`off`); collision follows. E.g. `STATE_guardian_defeated_off` rubble |
| `FX_<name>` | empty | A named point: `home_light` (beam on the horizon), `arena`, `beacon_lamp`, `ambush_<enemy id>_<n>` (spawned when you take the lens) |
| prop `light: "warm"` (+ `light_offset`) | any | Adds a warm point light (lantern posts, braziers) |
| material `TIDE_*` | material | Glows with the flood warning between the water and the high-tide line |
| material `GLOW_*` | enemy material | Telegraph glow driven by the enemy's threat |
| `PROP_<id>` | props.blend | Cloned by id (`assets.prop(id)`) |
| `MODEL_<enemy id>` | enemies.blend | Cloned per enemy; named parts are animated in code (`arm_l`, `arm_r`, `heart`, `claw_*`, …) |
| `VM_*` | viewmodels.blend | First-person models; a rod's `tip` empty anchors the fishing line |

Custom properties are Object Properties → Custom Properties; they arrive in Three
as `object.userData`.

## Materials & look

- **Principled BSDF only** (maps to `MeshStandardMaterial`). Flat colour per
  material plus vertex colour on terrain; no image textures yet.
- Stylised, chunky shapes, clear silhouettes, low poly.
- Emissive is gameplay language: **amber = safe/player/home**, **sea-green =
  supernatural/enemy**, **white-gold sparkle = loot**. Don't use sea-green emissive
  on anything harmless.

## Animation

There are no armatures yet. Enemies and viewmodels are animated in code by moving
named parts (see `src/enemies/*.ts`, `src/player/Viewmodel.ts`), which keeps the
models simple and the timing exactly in step with the attack windows. If a model
gets an armature later, name actions after the states (`idle`, `windup`,
`attack`, `recover`, `death`) and play them from the same state machine.

## Blockout first

Lay a location out as collision and markers first, walk it in game (the dev
console's `__ll.tp(x, y, z)` and `__ll.go("wreck")` help), then dress it.
